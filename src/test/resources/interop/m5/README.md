# M5 resource-provider fixtures (TEST ONLY)

The integration profile runs `NodeAccessTokenIT` and `KeycloakAccessTokenIT`; ordinary tests start no provider. Their helper generates a new two-day localhost/127.0.0.1 SAN certificate at each class start, trusts only that certificate through a scoped TLS context, and retains normal hostname verification. Containers bind only 127.0.0.1, use cached images with a never-pull policy, and are stopped after the class. Temporary TLS material is removed. No global trust store changes.

`keycloak-resource-realm.json` contains only public synthetic clients, user and test passwords. It uses the existing 26.7.4 image digest, explicitly opts one client into `access.token.header.type.rfc9068`, adds the real user-subject mapper, client_id, the intended resource audience and the authenticated introspecting client audience mappers (required by pinned Keycloak's provider-side introspection audience policy), and leaves the second client's JWT type unchanged for the deliberate `UNTYPED_ACCESS_TOKENS` profile with required azp. The explicit optional read client scope preserves its checked scope and never grants write. Existing OAuth/OIDC realm and tests remain unchanged.

The pinned node-oidc-provider 9.12.2 image keeps its existing default behavior. `TEST_RESOURCE_MODE=m5` enables real JWT resource indicators, client credentials, JSON introspection and revocation for the fixed test client. The pinned provider deliberately rejects structured JWT tokens at introspection/revocation endpoints; actual opaque resource tokens for `https://resource.example.test/introspection` cover those paths, while Keycloak covers genuine JWT introspection. The explicit node-provider JWT introspection error remains an infrastructure exception, separate from a credential rejection. JWT signatures are produced by the provider. Rotation restarts that same ephemeral provider container at the same issuer with fresh signing keys; the same Revetsec validator and JWKS cache validate the new real token. No fixture re-signing substitutes for provider issuance. A resource indicator identifies `https://resource.example.test/mcp`; it is an identifier and is never contacted.

Tests inspect checked proof and fixed result reasons. Credentials, private signing keys and response bodies are not printed or saved. Introspection observers count only the endpoint kind; repeated success/inactive validations each POST. Opaque node-provider revocation and Keycloak session revocation produce real inactive endpoint responses. Provider restart for key rotation resets ephemeral provider state and signing keys.
