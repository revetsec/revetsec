What is vendored

28 of the 343 files in the upstream testvectors_v1/ directory, plus the upstream LICENSE file. The 28 cover the
signature and MAC algorithms of JOSE that Revetsec verifies: JSON Web Signature and JSON Web Key cases; ECDSA over
P-256, P-384 and P-521 with the hash JOSE pairs with each curve, as fixed-length R||S (IEEE P1363); RSASSA-PKCS1-v1_5
with 2048-, 3072-, 4096- and 8192-bit keys and SHA-256, SHA-384 and SHA-512; RSASSA-PSS with the MGF1 hash and salt
length JOSE fixes for each hash, plus the miscellaneous-parameter file; Ed25519; and HMAC with SHA-256, SHA-384 and
SHA-512.

Nothing else from the upstream repository is vendored: no README.md or other Markdown, and nothing from schemas/,
doc/, vectorgen/ or tools/. Of the upstream vector files closest to that scope, these are deliberately left out:
  ed448_test.json                      Ed448 is not a supported curve
  json_web_crypto_test.json            a legacy combined file: 39 of its 40 distinct JWS values reappear in the JWS
                                       and JWK files
  json_web_encryption_test.json        JWE is not supported, and a handwritten case covers its rejection
  rsa_pkcs1_*_test.json                RSAES-PKCS1-v1_5 decryption and signature generation, not signature
                                       verification
  rsa_pss_*_params_test.json           keys that carry RSASSA-PSS parameters, which a JWK cannot express
  the other rsa_pss_*_test.json        hashes, MGF1 hashes or salt lengths JOSE does not use (the vendored
                                       rsa_pss_misc_test.json covers many such combinations)
  the other rsa_signature_*_test.json  hashes JOSE does not use (SHA-224, SHA-512/224, SHA-512/256 and SHA-3)
  the other ecdsa_*_test.json          curves Revetsec does not verify (secp256k1 and the Brainpool curves among
                                       them), DER-encoded signatures, or a hash JOSE does not pair with the curve
  the other hmac_*_test.json           hashes JOSE does not use

Every vendored file is byte-for-byte identical to the upstream file at the commit above: the content was not
modified, re-encoded or normalized in any way (no line-ending, whitespace or BOM changes). Each file's git blob
SHA-1 was also compared with the upstream tree at that commit, as the GitHub API listed it on 2026-09-26
(https://api.github.com/repos/C2SP/wycheproof/git/trees/3fa63dd0344abb611f1fb1d77e119938603ea230?recursive=1, not
truncated), and all 29 matched. Upstream marks none of them executable, and every vendored file is stored as a
plain, non-executable file.

The repository's .gitattributes marks src/test/resources/vectors/** as -text, so git never converts line endings
in these files.

Files added by Revetsec (not from upstream)

  SOURCE.txt       this file
  MANIFEST.sha256  SHA-256 of every other file in this directory tree, in sha256sum format, sorted by path

Revetsec's expected outcome for each vector is not recorded here: the test runners that use these files keep it in
their own expectation manifests, beside the runners.

Verifying

  cd src/test/resources/vectors/wycheproof && shasum -a 256 -c MANIFEST.sha256
  (or: sha256sum -c MANIFEST.sha256)

The test helper com.revetsec.testing.WycheproofVectors checks the manifest in both directions, then recomputes every
column of the table above from the files and checks that each file is a well-formed vector file, before it hands
any vector to a test; any difference fails the build. com.revetsec.WycheproofManifestTests pins the commit, the 28
file names, their counts and their git blob SHA-1s. These files are used only by tests. They are not in the
published JAR.
