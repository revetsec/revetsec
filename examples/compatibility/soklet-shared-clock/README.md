# Temporary Soklet adapter test compatibility

The adapter production sources and POM at `3bad3251bb9b3bd2baeecd5c55a41574c8ebb9b0` compile against current core. That commit's issuer test fixture still implements the earlier `Optional<OAuthStoreEntry>` / `OAuthStoreCommitStatus` store API. Compiling it against the shared-clock API fails before example qualification can run.

This directory supplies an explicit **test-only replacement** for that issuer fixture. It is derived from the already-authored Soklet shared-clock test conversion and retains the original tests, adding final-consumption and uncertain-outcome coverage. The helper comes from current core's canonical `src/test/java/com/revetsec/testing/ScriptedOAuthStore.java`. The adapter's upstream tests are therefore a pinned snapshot with a declared replacement; they are not represented as an unaltered upstream test suite. No adapter production code, POM, or published artifact is patched.

`manifest.json` records the exact adapter revision, original issuer fixture SHA-256, replacement fixture SHA-256, canonical helper SHA-256, and the two supported shared-clock carrier hashes. `verification/examples/adapter_compatibility.py` applies the replacement only to the builder's disposable adapter copy. It verifies every pinned POM/production input against Git, requires all other adapter test inputs to remain pinned, validates every replacement before writing either file, and compares the selected production and test inputs again after the build. The complete 169-test adapter suite must pass without skips; no adapter test compilation or execution is suppressed. CI uploads its Surefire reports.

The builder's `ADAPTER-COMPATIBILITY.json` and `RESULT.json` record the original/input/replacement fixture hashes separately, the helper source and input hashes, all selected test inputs, production/POM hashes before and after, and actual test totals. A locally preconverted issuer fixture is accepted only at the declared replacement hash. The manifest also recognizes the exact inherited helper hash from before its canonical static-analysis correction; the disposable copy always receives the checked canonical helper. Unknown dirty tests or helper bytes fail closed.

For the default legacy core pin, both shared-clock carriers are absent: the replacement is skipped and every adapter test remains exactly upstream. The default core pin is the already-pushed `0e5c54259e09f7c33d57d22d1de1760e3a267102`; the earlier `2a7238818a7a7ef38a6c93645e679f200165a147` predates the `JwksPublisher.Builder.httpCacheMaxAge` API used by the pinned adapter's unchanged tests. CI continues to pass its current run revision explicitly. A partially present SPI or unrecognized carrier source fails closed. The compatibility guard tests run in both examples CI lanes; they exercise corrupt base/replacement/helper hashes, wrong revision, unknown tests, partial/unknown SPI, production drift and incomplete test execution.

Remove this bridge after a compatible Soklet adapter revision has been committed and pushed by its owner, pin that immutable revision, and verify the full adapter and example suites on JDK 21 and 27 without a replacement. `examples/pins.json` deliberately continues to name the existing immutable adapter commit until then.
