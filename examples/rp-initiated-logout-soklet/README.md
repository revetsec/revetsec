# Local-first RP-Initiated Logout with Soklet

This unpublished Java 21 carrier composes the [common Java 17 logout recipe](../rp-initiated-logout/README.md) with the selected Soklet request/route/cookie types. Supply an existing authorized session backend using atomic stored-session CSRF verification and close, a configured OIDC client, and a qualified confidential/integrity-protected atomic pending store. No core or adapter API is added by this cookbook.

The backend binds private IPv4 loopback. Enable `trustedHttpsAndQueryFreeStartEdge` only after an authenticated/private HTTPS edge preserves a fixed trusted Host and rejects **every raw query delimiter on POST `/logout`**, including a bare trailing `?`, before Soklet parses the target. The selected PIN56 framework collapses that empty delimiter to absent query; the public request value cannot recover it. With otherwise valid session/CSRF credentials, direct backend `/logout?` can close the session when the capability is asserted without a real edge. This is an explicit deployment/profile gap, not a successfully tested rejection. GET `/logout/callback` deliberately permits the bounded raw state query. Never derive transport trust from forwarding headers or expose the private listener publicly.

The listener caps connections at 64, handlers at 16 and the queue at 16; the common application separately admits eight operations without a queue. Request headers are limited to 32/8 KiB, bodies to 4 KiB and raw targets to 8 KiB. Header/body reads have three-second limits, handlers six seconds, response idle writes three seconds. The common application keeps its own original four-second budget and requires a client deadline of at most three seconds. Preserve complete-body/discard status, raw path/query, header/cookie multiplicity, actual socket peer and separate response cookies. A parser/transport rejection before an application callback may close the connection without delivering a cookie-clearing response; do not claim otherwise.

After injection use `Soklet.run(recipe.configuration(privatePort))`. Register only this recipe's fixed `/logout` and `/logout/callback` routes. The application first closes its own session, then attempts provider request preparation and one pending save. Only SAVED emits a credential-bearing Location/form. FORM_POST is the common default; GET is a trusted startup choice capped at 4096 URI bytes. Failures never restore a local session or retry a possibly effectful operation. The return clears only the pending cookie, preserves a newer application session and proves correlation only. Cleartext request/response/Location/body/cookie/provider logging is disabled. Do not deploy the test-only OP/bootstrap/fault controls.

Local component tests and real socket checks do not qualify the actual HTTPS/query-rejection edge, hosted provider/browser interoperability, durable multi-node sessions/stores or the complete release candidate. Those gates remain explicit.
